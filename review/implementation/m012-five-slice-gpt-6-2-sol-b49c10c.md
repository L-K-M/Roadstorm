## Findings in severity order

1. **Medium — Hairpin runner continues after cancellation and can signal a stale PID.** `tools/calibration_hairpin_physical_lab/run_validation.sh:174–182,217–228,239–247,392–395`. HUP, INT and TERM run the same cleanup function as EXIT. The handler removes the scratch and returns to the interrupted control flow. It does not terminate or explicitly reap the supervising timeout process. In particular, a timeout wrapper still waiting for the coordinator lock can outlive cancellation when `godot.pid` is empty. The same function reads a numeric PID after waits and again at final cleanup, tests only liveness, and sends TERM then KILL without a process-identity check. A reused PID can belong to a different process. Reproduction: `sol-private/hairpin-runner-control.sh` uses the candidate's exact cleanup functions and traps with mock PID signalling. TERM to the test shell printed `CONTINUED after TERM with scratch removed`; its stale-PID stand-in received mock `kill -0`, `kill -TERM`, and `kill -KILL`. No real unrelated process was signalled. Cancel and reap the owned supervisor before removing its scratch, exit with a cancellation status, and stop signalling an engine PID once its invocation has been reaped.

2. **Low — Cosmetic retries are counted twice.** `src/presentation/cosmetic_damage_state.gd:494–528,595–603,746–752`. Both duplicate branches increment `coalesced_count` before calling `_coalesced()`, which increments it again. Reproduction: `sol-private/cosmetic-retry.gd` accepts one 2.0 m/s hit, repeats the exact event and then sends a second ID with the same contact. The two calls each report one coalesced outcome and emit no cue. `diagnostics().coalesced_events` reads 0 → 2 → 4. The stock tests check outcomes and unchanged content digests at `tools/cosmetic_damage_lab/cosmetic_damage_lab_checks.gd:246–267`. The digest excludes diagnostic counters, so those checks miss the error.

3. **Low — Cosmetic fingerprint omits the order that controls contact eviction.** `src/presentation/cosmetic_damage_state.gd:607–614,713–720,800–811`. `content_digest()` promises to cover retained identity state, but sorts retained contacts before encoding them. FIFO order determines which future retries will coalesce. Reproduction: `sol-private/cosmetic-digest.gd` configures two reducers with event capacity 1 and contact capacity 3. At one tick they consume A/B/C and B/A/C respectively, with identical 0.25 m/s severities. The digests compare equal. After D, retrying A is accepted by the first reducer and coalesced by the second. Fingerprint the FIFO order so distinct continuation behavior is visible to the digest-based checks.

4. **Low — Practice teardown test misses HUDs outside the current scene.** `tools/practice_flow_lab/practice_flow_lab.gd:158–175,292–318,349–359`. Cameras are counted from the root viewport. The active check only verifies presence of the expected HUD and layer, and the teardown check scans CanvasLayers below the returned menu. Reproduction: the private `practice-teardown-control.gd -- --add-root-hud` subclass places an additional CanvasLayer with a Label at the root during the first practice entry. It survives both returns, while all 31 stock checks still pass. The unmodified run had no injected HUD. The test should check the HUD's instance lifetime and root-wide leftovers against the intended overlay/HUD ownership.

The hairpin runner's `--expect-sha` protects the declared base input, while the documented lab overlay comes from the invocation checkout (`tools/calibration_hairpin_physical_lab/run_validation.sh:140–155,249–264`). Its wrapper summary alone is insufficient to attest exact-candidate lab bytes. The archive-direct checks below cover those bytes.
