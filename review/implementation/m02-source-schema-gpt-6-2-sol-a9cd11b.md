## Ranked findings

For the document mutations below, start from `fixtures/car_recipe/positive/example_rookie_finite.json` and recompute its source `content_hash` unless the case concerns parsing or hashing. These are source-traced reproductions. I independently confirmed the relevant Python behaviors listed under verification.

1. **High — The checker accepts `{"unlimited": 1}` and `{"unlimited": 1.0}`.** Replace the yaw cap with either object. Python dictionary equality considers these values equal to `True`, so `_validate_max_yaw_rate` exits before its `is True` check. Both checker modes can accept the recipe, while the schema’s `const: true` requires the actual JSON boolean. This bypasses the explicit authored decision to disable the cap. Require the exact key set and `value["unlimited"] is True` in the successful branch. Add rehashed numeric-sentinel negatives with a yaw-specific diagnostic assertion. See `tools/car_recipe_schema/validate_car_recipe.py:868–896`, `schemas/handling_config_v1_1.schema.json:512–535`, and `tools/car_recipe_schema/tests/test_car_recipe_schema.py:293–319`.

2. **High — The checker skips required fields and object types inherited from v1.0.0.** Delete `dimensions.wheelbase_m`, replace `upgrades.engine` with `[]`, or append a detachable part with valid `slot`, `mesh_id`, `lod_ids`, `attachment_transform` and `impact_region` but `thresholds: []`. Each mutation leaves the checker without a finding for the bad member. Missing nullable dimensions are read via `.get()`, and upgrade subobjects and detachable thresholds are only validated inside successful `isinstance(..., dict)` branches. `contact_proxy.roof` and `underside` have the same presence gap if the corresponding unknown entry is removed. In the opposite direction, an empty `roof`, `underside`, detachable `mesh_id` or surface `notes` string is schema-valid but rejected by the checker’s default minimum length of one. Enforce presence separately from nullability, diagnose wrong object types, and use the schema’s actual length constraints. Add table-driven parity cases in both versions. See `tools/car_recipe_schema/validate_car_recipe.py:431–450, 539–592, 639–653, 1021–1118, 1133–1174` and `schemas/handling_config.schema.json:56–79, 243–291, 315–344`. These constraints are unchanged in v1.1.0.

3. **High — `motor-ready` accepts an acceleration curve rejected by the typed resource.** In `handling.acceleration_curve`, change the second point’s speed from `30` to `0`, or reverse the two points. The checker validates each point and rejects an empty list in motor-ready mode. It never compares adjacent speeds. `HandlingDefinition` requires strictly increasing speeds. Preserve the historical schema-mode shape and enforce ordering in motor-ready mode, with duplicate and descending-speed regressions. See `tools/car_recipe_schema/validate_car_recipe.py:595–614, 1295–1325`, `src/data/handling_definition.gd:155–195`, and `tools/car_recipe_schema/tests/test_car_recipe_schema.py:450–466`.

4. **Medium — Numeric and Unicode edge cases escape controlled refusal.** Put a 401-digit integer in the yaw cap or an unbounded reverse field. The parsed Python `int` reaches `math.isfinite`, which raises `OverflowError` during conversion. Put the escaped lone surrogate `\ud800` in `display_name` and hashing raises `UnicodeEncodeError`. Put the raw number `1e999` in `presentation`, an open object, and Python loads it as infinity. The checker only checks finiteness along typed numeric paths, and `json.dumps` can canonicalize the payload with the non-JSON token `Infinity`. A digest computed from that representation can therefore pass the hash comparison. Reject unrepresentable numbers and strings with path-level findings, make canonical serialization refuse non-finite values, and exercise these cases through the file entry point. Also test decimal literals immediately outside strict bounds, such as a trigger of `1.00000000000000001`, which rounds to `1.0` before comparison. Define where decimal validation ends and runtime float conversion begins. See `tools/car_recipe_schema/validate_car_recipe.py:251–305, 344–376, 897–904, 1267–1287, 1392–1398`. The current overflow test at `tools/car_recipe_schema/tests/test_car_recipe_schema.py:321–325` assigns an already-evaluated Python float and never tests file parsing.

5. **Medium — The null traversal and dotted-path resolver disagree for open object keys.** `presentation` permits arbitrary keys. A literal `presentation["paint.color"] = null` is collected as `presentation.paint.color`, which resolves to a nested member if one exists. With both a literal `"paint.color": null` and a nested `"paint": {"color": null}`, one entry can appear to explain two distinct values. Other allowed keys, such as `paint-id`, cannot be named by the checker at all. Define which open subtrees participate in the honesty rule, then make participating paths unambiguous and representable. Keep the exact `handling.<field>` requirement for the five new inputs. See `schemas/handling_config.schema.json:81–84` and `tools/car_recipe_schema/validate_car_recipe.py:76–78, 316–321, 461–495, 1191–1252`.
