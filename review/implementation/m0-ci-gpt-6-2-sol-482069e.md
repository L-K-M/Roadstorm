## Ranked findings

1. **P1 — The lock filenames can themselves be export destinations.** `tools/ci/ci.sh:1856–1864,1896–1903,1937–1958`. With a gated engine stub, start A with `--out pkg/namespace.exe.ci-lock` and wait until it reaches export after its stale-output check. Start B with `--out pkg/namespace.exe`. B takes a disjoint pair of locks, creates the empty file `pkg/namespace.exe.ci-lock` at A's destination, and reaches its engine. Release A and it writes to that same file. I observed the empty file after B and A's engine bytes after release. Both commands entered the engine, and both stopped short of inventory PASS in the fixture. This uses ordinary cooperating invocations and no pathname replacement. Reserve a lock namespace that cannot overlap either engine output, or reject such export destinations before using the lock namespace.

2. **P1 — Concurrent exports sharing the normal evidence directory also share a mutable project copy and engine logs.** `tools/ci/ci.sh:264–268,1954–1958`, `tools/ci/lib/common.sh:113–129,622–626,667–696`, `tools/ci/tests/run_tests.sh:2387–2401,2474–2479`. Static counterexample: hold a same-preset export in Godot, then start a second export for a different destination with the default `CI_OUT`. B can enter while A is running, recursively clear A's active `project-copy`, recreate it at the same path, and truncate A's preset/sequence engine log. The candidate's concurrent tests give each attempt its own output directory, which avoids these shared paths. Give concurrent attempts independent project copies and logs, or explicitly serialize access to a shared workspace and document that requirement.

3. **P1 — Report token reservation ends before the evidence is written.** `tools/ci/lib/common.sh:1025–1069`, `tools/ci/ci.sh:1838–1842,1923–1927,2057–2068`. `mktemp` exclusively creates the temporary pathname, then `mv` releases that reservation and can replace existing final evidence if that token is drawn again in the same second. At a frozen timestamp I forced the same suffix with a fixture that honors exclusive creation of the temporary pathname. A `pin --field tag` command exited 0 and replaced a seeded prior report. For the preset rename I seeded a dangling symlink at the known final path. The `-e` test missed it, and `mv` replaced it with the report. The two renames also permit a failed outer rename followed by a successful inner rename without updating the parent path. Reserve the final evidence identity exclusively, retain that reservation for the lifetime of the evidence, and fail if the report cannot be opened. A prior inventory with a reused token can also be mistaken for current evidence when the new checker fails before writing its report.

4. **P2 — The nested dispatch can run the export without locks.** `tools/ci/ci.sh:1907–1911,1937–1958,2115–2122`; `tools/ci/lib/common.sh:1017–1023`. With an ordinary export held at the engine seam, a second invocation of `ci.sh … __export-inner 'Linux probe' release "$absolute_destination"` reached the engine for the same destination while the first was still live. The worker is directly dispatched and accepts inherited report metadata without a command or lock ownership check. Keep unlocked export logic out of direct CLI dispatch, or make the worker validate a lock handoff and constrain the inherited report metadata to that handoff. This is a local correctness guard, since an unrelated writer can always ignore advisory locks.

5. **P2 — Persistent coordination files are published as package files.** `.github/workflows/ci.yml:395–419,448–454`, `tools/ci/ci.sh:1856–1864`. A normal build creates `build/<destination>.ci-lock` and `build/<sidecar>.ci-lock`, including a sidecar lock for a preset that never writes a sidecar. The package uploader selects all of `build/` with no exclusion. The local probe observed persistent files after the export workers exited. Exclude the coordination files from the package artifact while retaining the locks in the build directory.

6. **P2 — Engine failure output regressed.** `tools/ci/ci.sh:1958–1974`, `.github/workflows/ci.yml:422–438`. The base implementation defined `ci_print_export_failure_log`, and the candidate deletes the definition while leaving three calls. With an export stub that exits 9 and prints an indented diagnostic, the command exited 1 with `ci_print_export_failure_log: command not found`. The zero-write branch behaved similarly. The engine diagnostic remained in the raw log and was absent from the command transcript. Restore the helper and check the transcript on at least one engine failure.

7. **P2 — Export loses the global project-copy options through the lock handoff.** `tools/ci/ci.sh:189–195,304–313,1882–1890`, `tools/ci/lib/common.sh:667–681`. The new process resets `CI_IN_PLACE` and `CI_REUSE_COPY` and does not receive either flag. I ran `--in-place … export --export 'Linux probe'` and observed scratch preparation and Godot receiving the scratch project path. Dropping `--reuse-copy` follows from the same dispatch. Forward the existing options with the other worker inputs.

## Lock behavior and limits

- On macOS `/usr/bin/lockf`, an export for `shared.exe` held its sidecar lock while an invocation targeting `shared.pck` directly timed out with exit 75. A disjoint destination reached the engine while the holder was gated. The probe used distinct evidence directories. With unchanged pathnames and normal distinct lock inodes, both lock utilities are invoked around the stale-output check and the entire export and inventory operation. Parent canonicalization accounts for stable symlink traversal for ordinary path components.
- A pre-existing regular lock file retained its seeded bytes. A dangling lock symlink and a lock directory were refused and preserved, and an existing output directory was refused and preserved. A second attempt on the same destination reached the engine using the retained lock files after the first worker completed. I did not test Linux `flock`, a process-group crash, or SIGTERM against the actual locker. The suite signals the outer shell PID and retries with a wait, so its result alone would not establish immediate lock release on outer-shell death while a worker is active.
- **Advisory limitations.** Unrelated writers can ignore a lock. Unlinking or replacing a lock pathname can let another invocation open a new inode. The pathname checks also precede the actual open, so a hostile swap can change what the locker opens. These are distinct from finding 1, which needs no interfering writer. Stable aliases are a separate edge case. The deduplication is textual, so lock names differing only by case can alias a single inode on a case-folding volume, or pre-existing hard-linked regular lock names can alias even on a case-sensitive volume. Nested acquisition can then contend with itself. The case-folding probe was unavailable on the actual scratch volume.
- **Quoting and diagnostics.** Spaces and apostrophes in the engine path and destination reached the engine intact. Line-delimited path normalization and lock sorting do not round-trip embedded line feeds, and `_shq` uses command substitution, which strips trailing line feeds. This was inspected rather than exercised. Explicitly rejecting unsupported path inputs would avoid ambiguity. Normal export also suppresses the report-location diagnostic in both the parent and worker after exporting `ROADSTORM_CI_REPORT` (`tools/ci/ci.sh:1882,2142)). The report was still present and contained the supplied full SHA and failure verdict. Restoring the report pointer and recording a structured timeout verdict would improve diagnostics. The inventory filename uses a SHA prefix plus the attempt token. The success report links the inventory and binds the full supplied SHA, and PASS follows a successful checker exit. These are associations with caller-supplied metadata. I did not run Godot or the real inventory checker.
