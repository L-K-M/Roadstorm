### Ranked findings

1. **P2 — Report identity can survive on paper after the original file is gone.** The code records a device/inode pair from the private body, removes the private name, and passes the pair to the nested worker as text. The append helper opens the current pathname and compares its `fstat` result against that pair. The hosted regressions invoke `__export-inner` directly with an already-final report name, so the publication helper returns immediately and the fixture has only one link to the original file. The writer unlinks that file and creates a same-header replacement before it exits. If the filesystem recycles the inode number, the replacement passes both the first-line header check and the identity check. The supplied Ubuntu results demonstrate the consequence: case 244 appended FAIL to the foreign report, and case 246 appended PASS and printed export success. Inode reuse explains both outcomes without a race between the final check and append. The supplied evidence does not include an inode trace confirming reuse directly. [common.sh:1110](tools/ci/lib/common.sh#L1110), [common.sh:1174](tools/ci/lib/common.sh#L1174), [common.sh:1307](tools/ci/lib/common.sh#L1307), [ci.sh:2144](tools/ci/ci.sh#L2144), [run_tests.sh:3707](tools/ci/tests/run_tests.sh#L3707), [run_tests.sh:3774](tools/ci/tests/run_tests.sh#L3774)

   The normal outer path retains the generic report as a hard link, so deleting the preset name alone cannot free the original inode there. The direct-inner cases expose the missing lifetime guarantee in the handoff itself. Bind the private body to a live descriptor before publication and keep that descriptor open through the nested worker and verdict. Require a live reference for inherited reports. For verdicts, open the publication name without `O_CREAT`, use `O_NOFOLLOW` and a nonblocking open, and check that the opened object is regular and matches the held reference before writing through the checked descriptor. This gives the comparison a live original and prevents a missing path from being recreated. Keep both direct-inner regressions and add coverage for the normal outer-to-inner handoff.

2. **P3 — A checked append can still lose its visible evidence before success is printed.** The existing `fstat` protects the object behind the opened descriptor. If the published name is unlinked or replaced after that open, the write still lands on the opened file. The helper can then return success even though the advertised path has disappeared or points elsewhere. The pre-open shell symlink check also leaves a window in which the helper can follow a symlink or block opening a FIFO. Recheck that the published name still identifies the held report after appending and before emitting success. This catches observable loss of attribution. A same-user process that can rewrite or remove the file after the final check can still invalidate the evidence, so describe that limit explicitly. This timing issue is separate from the two observed Ubuntu failures, where replacement happens before the append helper opens the file. [common.sh:1140](tools/ci/lib/common.sh#L1140), [common.sh:1174](tools/ci/lib/common.sh#L1174), [ci.sh:2548](tools/ci/ci.sh#L2548), [README.md:122](tools/ci/README.md#L122)

3. **P3 — Hosted CI can silently skip the real `ln -T` regression.** The suite has a genuine host-`ln` case with Python disabled, alongside the emulator and broken-linker cases. The workflow requires the emulator and broken-linker results by name, but omits the real fallback result. The real case's capability probe can therefore skip and leave Ubuntu green. Require the real fallback success line on `ubuntu-latest`. The implementation's `ln -T --` uses an exact destination, classifies an occupied destination after failure, and fails fast on other errors. [common.sh:1283](tools/ci/lib/common.sh#L1283), [run_tests.sh:3820](tools/ci/tests/run_tests.sh#L3820), [ci.yml:402](.github/workflows/ci.yml#L402)
