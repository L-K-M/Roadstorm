## Ranked implementation findings

1. **P2 — Explicit export mode bypasses the pre-engine guard.** The early parser reads `--mode` only *before* `--export`. The real parser consumes the subcommand first, then accepts `--mode debug` or `--mode=debug`. The early parser therefore stops without reading `--out` on a valid request such as `export --export --mode debug "Linux x86-64" --out ./pkg.CI-LOCK`. It returns 0, allowing `ci_find_godot` to invoke Godot with `--version`. The later guard still prevents the export writer and destination lock acquisition. Parse and validate the build request once before the version probe, and add zero-invocation tests for both mode spellings. `tools/ci/ci.sh:295–324`, `:398–412`, `:1684–1707`, `:1984–1992`, `tools/ci/lib/common.sh:405`.

2. **P3 — A literal newline in the destination also bypasses the early guard on both entry points.** The early parser serializes the request as three newline-delimited fields. The guard keeps only the first line of the destination. A path containing `line`, a literal newline, then `end.CI-LOCK` returned 0 for both the outer and direct-inner guard in the read-only probe. Preserve the argument without line serialization, or reject unsupported pathname characters before engine discovery. `tools/ci/ci.sh:324–350`.

3. **P3 — A missing report source bypasses the publication failure branch.** Both call sites attempt publication only if `CI_REPORT` already passes `-f` and the attempt ID is nonempty. If the reserved source disappears before that condition, the build continues without publishing the preset-specific name. The final append can recreate the file without its attempt header and still return success. This is a residual case outside the occupied-destination fix. Make an invalid or missing report source or attempt ID an explicit failure at both publication sites. `tools/ci/ci.sh:1963–1972`, `:2113–2122`, `:2403–2406`, `tools/ci/lib/common.sh:1042–1048`, `:1100–1104`.

I found no new P0 or P1 defect in the reviewed paths.
