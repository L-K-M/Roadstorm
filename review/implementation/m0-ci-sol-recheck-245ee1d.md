## Remaining findings

1. **Low — An output path with `..` after a symlink can write to a different directory.** `tools/ci/lib/common.sh:1175–1185` lexically removes components. I made sibling directories `caller` and `elsewhere/inner`, made `caller/via` point to `../elsewhere/inner`, then ran from `caller` with the pinned engine and `export --export 'Linux x86-64' --out 'via/../package'`. Normal filesystem lookup of `caller/via/../package` reaches `elsewhere/package`. The wrapper returned 0, wrote the binary and PCK to `caller/package*`, and left the requested path absent. `tools/ci/ci.sh:1788–1793` already creates the destination's parent before normalization, so it can resolve that parent through the filesystem and append the output basename. Ordinary workflow paths are unaffected.
2. **Low — The export log artifact includes the scratch project and loses prior per-preset logs.** `.github/workflows/ci.yml:367–374` uploads all of `tools/ci/out/`. Hosted logs record 498 uploaded files and a 101,719,222-byte archive. `tools/ci/lib/common.sh:72,113–117,624–635` gives each successive preset invocation the same engine log names and stores the project copy below the upload root. The hosted console shows each preset using the same `export-2-export.log`, so later presets replace earlier engine logs. Console output and separate timestamped reports retain the outcomes. Per-preset output directories and an upload scoped to logs and reports would preserve the engine evidence without copying project data into this artifact.
