1. **P2 — Inventory preflight and checker use different Python startup modes.** `tools/ci/ci.sh:330–331` probes `python3 -I`, while `:2428` starts the actual checker without isolation, after the writer at `:2313`. The report linker also uses `-I`, so reservation can succeed in that environment and the package writer can run before the checker fails. The workflow still withholds the failed package set. Use the same interpreter and startup flags for preflight and checking, and add a failure-path test that asserts the writer stays untouched.

2. **P3 — A partial report-body write can still reach publication.** `tools/ci/lib/common.sh:1077–1090` checks the status of a compound command containing seven `printf` calls. An early write failure followed by a successful final `printf` yields success for the group. In a no-write `dash` probe, I forced the first `printf` to fail and let later calls succeed. `ci_init_report` reached the linker stub and returned **0**. A separate probe confirmed that a failed output redirection exits **2** before linking. Check the entire write before publication, for example with one `printf` or an explicitly checked sequence, and cover a failed header write with a succeeding later write.

3. **P3 — The final report check establishes a text match at a pathname, with no continuity of file identity.** `tools/ci/lib/common.sh:1119–1124` accepts any exact matching line, including a report whose first `attempt-id:` names another attempt. My probe accepted `attempt-id: wrong` followed by `attempt-id: expected` when checking for `expected`. The final check at `tools/ci/ci.sh:2506` then uses a separate pathname append at `:2509` via `common.sh:1112`. A replacement carrying the matching line can pass, and the documented unlink window can still let `>>` create a headerless PASS file. A related failure path at `ci.sh:2314–2318` can recreate a report deleted by a writer that exits nonzero, this time with a headerless FAIL. Require a single authoritative attempt header and bind export verdict writes to the reserved file, without creating missing paths. Recheck both successful and failing writer paths.
