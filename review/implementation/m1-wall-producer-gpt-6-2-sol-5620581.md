A caller that emits every witness with fresh IDs can also send repeated zero or small-delta events during sustained contact. The ledger bounds retained records and coalesces identical IDs within its window. Fresh IDs on unlinked wall events bypass the pair check (`impact_event.gd:568–581,668–716`). Decide whether zero-delta contacts emit, who owns sustained-contact suppression, and how retry identity is reused. Add a zero-delta fixture and exercise consecutive same-wall ticks at coordinator integration. This is a potential delivery-rate issue, with no live producer call site or observed flood in this candidate.
2. **Low, implementation defect on malformed input. Published post velocity can differ from canonical state.** `wall_impact_producer.gd:129–137,160,174` accepts a witness within 1e-6 m/s of the mapped committed velocity, then builds both severity and the post field using the witness value. With committed zero and witness post `Vector3(0, 5e-7, 0)`, an off-plane post passes and is copied into an otherwise valid event. The current adapter maps an exactly planar post through the fixed sign/axis conversion, so this is outside genuine adapter output. Require exact mapped agreement on this seam, or explicitly canonicalize the accepted post for both fields if tolerance is intentional. Add a near-tolerance off-plane fixture. The current test only exercises a large disagreement (`wall_impact_lab_driver.gd:524–531`).
3. **Low, missing regression evidence. Strengthen the physical oracle and ledger assertions.** The real Jolt fixture exercises a single selected witness from a head-on run. The independently expected FRONT and +Z normal give meaningful checks. Assert a physical severity/post result directly and add a tilted or yaw-constrained real producer case when extending the lab. The synthetic rotated-frame and tilted-normal cases already discriminate these choices in producer code. Explicitly require successful builds before the conditional cross-tick and duplicate-perspective assertions at `:688–715`. The README claims capacity coverage, while the publication case stops at two stored records on its ledger and exercises no over-capacity refusal (`:614–733`); either narrow the claim or add that case.
