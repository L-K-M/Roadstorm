2. **Medium — The cadence check accepts frame totals that cannot contain the recorded run.** At `tools/frame_trace_lab/compare_frame_traces.py:189–213`, the only individual counter bound is positivity. Set `timing.physics_frames` and `timing.process_frames` to 1 in the frozen 60 trace and leave its 1,200 committed rows and callback evidence intact. The comparator exits 0 with `"pass":true`. The driver measures these counters before starting the lab through the end of the drain (`frame_trace_driver.gd:130–148`), so one physics frame cannot cover those commits. Require a physics-frame count consistent with the 1,200-tick run before using the ratio as evidence. Reproduction in `logs/impossible-counters.json` and `logs/impossible-counters.log`.

3. **Medium — A large JSON integer crashes the new cadence path.** At `tools/frame_trace_lab/compare_frame_traces.py:195–205`, a positive Python integer passes the guards but its float conversion may overflow. Set only `timing.physics_frames` to the JSON integer `10**400` as expanded digits. The comparator exits 1 with `OverflowError: int too large to convert to float` and emits neither structured failure marker. Bound the counters before conversion or compare in integer arithmetic using the exact inequality `abs(process_frames * 60 - physics_frames * nominal_fps) <= 4 * 60`. Reproduction in `logs/overflow.json` and `logs/overflow.log`.
