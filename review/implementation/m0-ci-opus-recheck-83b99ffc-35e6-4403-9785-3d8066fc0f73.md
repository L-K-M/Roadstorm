## Findings at 8c6c928, ranked

### Medium

**R1. Report files are named to the second and opened with truncation, so the `export --check` report is destroyed. The new per-preset rename then moves the shared file away. The uploaded `export-logs` contains no `export --check` report.**

- **Evidence (hosted):** one file name, `tools/ci/out/reports/export-20261127T023153Z.txt`, is announced by three processes:
  - the `export --check` process (line 825);
  - the `export --list-presets` producer (line 853);
  - the macOS `export --export` process, which renames it to `export-macos-apple-silicon-20261127T023153Z.txt` (line 868).
- **Cause:**
  - `ci_init_report` (`common.sh:1013-1024`) names the report `${CI_RUN_NAME}-<UTC second>.txt` and writes it with `>`, which truncates.
  - All three processes started within the same second, so each truncated the previous one's report.
  - `ci_export_build` then `mv`s the shared file to its preset name (`ci.sh:1828-1836`).
- **Count check:** the upload holds 21 files.
  - Logs: 6 (2 per preset).
  - Reports: 15 — 4 `pin`, 2 `verify-engine`, 2 `verify-templates`, 1 `install-templates`, 3 per-preset `export`, 3 inventory.
  - A surviving check report would make it 22.
  - The same collision also merged two `pin` reports (lines 758–759). Those are low value.
- **Impact:**
  - The templates-and-presets verification report, which is M0.5 export-preparation evidence, is missing from the artifact. It survives only in the step's console output.
  - The rename can also move a file that belongs to another invocation. This is the same class of evidence loss F1 was about.
- **Fix:**
  - Make report names unique per process, for example by adding `$$` or a `mktemp` suffix, and never truncate an existing report.
  - Have `ci_export_build` create its own preset-named report instead of renaming the shared one.
  - Optionally, write no report for pure data commands (`pin`, `--list-presets`).
  - Add a self-test case that starts two `ci.sh` invocations in the same second and asserts that both reports survive.

**R2. On a reused output path, leftovers can stand in for a missing package. `ci_export_build` does not remove a previous `$_out`, sidecar `.pck` or inventory report before exporting.**

- **Code:**
  - Nothing between `ci.sh:1800` and the engine call at `1842` deletes `$_out` or `$_pck`.
  - The checks that follow test only that the files exist and are non-empty:
    - `[ ! -s "$_out" ]` at 1854;
    - `[ -e "$_pck" ]` at 1889.
  - The inventory report path is fixed per slug (`ci.sh:1945`).
  - `pack_inventory.py` exits through `die()` before writing `--report` when a component is empty or the `.pck` cannot be parsed (`pack_inventory.py:621-634`).
- **Failure scenario (inference from code, not executed):** a developer or reviewer runs `ci.sh export --export "Linux x86-64" --out build/L` twice, and the second engine run exits 0 without writing.
  - The first run's `build/L` and `build/L.pck` satisfy every check, and the inventory "passes" on the old pack. This is exactly the silent "exit 0 / no output" mode that M1 was about.
  - Likewise, if a later inventory run dies early, `ci.sh` reports FAIL but points at `export-package-inventory-<slug>.txt`, which still holds an earlier `verdict=PASS`.
- **Exposure:** hosted CI is not affected, because `actions/checkout` cleans the work tree, so `build/` and `tools/ci/out` start empty. `ci.sh` is the documented entry point for local and reviewer runs, so those are affected, and so is a persistent runner with `clean: false`.
- **Fix:**
  - `rm -f "$_out" "$_pck" "$_inv_report"` (after the path checks) before invoking the engine. Alternatively, refuse to run if they exist.
  - Make `pack_inventory.py` write a FAIL report on its `die()` paths.
  - Add a self-test with a pre-seeded stale output.

### Low

**R3. Export evidence is not bound to the source SHA.**

- The export job calls `ci.sh` without `--source-sha` (`ci.yml:331, 341, 360`; hosted line 801).
- The checks job passes it (`ci.yml:106-121`).
- The export reports therefore record `source-sha: not recorded` (`common.sh:1023`), and the inventory reports carry no SHA at all.
- The run itself is tied to the SHA, but the downloaded artifacts are not.
- **Fix:** pass `--source-sha "${{ github.sha }}"` to every `ci.sh` call in the export job, and record it in the inventory report.

### Nits

- **Stale comment.** `ci.yml:367-369` still describes `project-copy` as "~100 MB with earlier packages", but `./build` is now excluded from the copy.
- **Wrong template version in the inventory report.** `pack_inventory.py:template_identity` picks the lexicographically last directory under `export_templates` (`sorted(...)[-1]`), not the pinned version. On a host with several versions the template-identity line can compare against the wrong template. This is report-only and does not affect the verdict.
- **Preset name used as a regex.** `ci.sh:1812` uses `grep -qx "$_preset"`, so `.` in a name matches any character and a leading `-` is read as an option. It fails closed through the engine, but `grep -Fqx -- "$_preset"` is the intended check.
- **Slug collisions.** `ci_preset_slug` maps presets that differ only in case or punctuation to the same slug, and they would then share logs and reports. The current three are distinct, and a self-test case pins them.

### Checked and found sound

- **Path safety:**
  - `--out` is made absolute against the caller's directory and resolved component by component (`ci.sh:1800-1805`). The hosted run shows absolute `build/…` outputs.
  - Slugs contain only `[a-z0-9-]`, so a preset name cannot escape `logs/` or `reports/`.
  - The macOS inventory extracts into a fresh `mkdtemp`, which is removed in `finally`. `zipfile.extractall` strips absolute and `..` member names.
- **Fail-closed inventory wiring:**
  - An unknown platform, a missing tool, a missing `python3`, rc 1 and rc 2 each return `CI_FAIL` with a report line.
  - Output is captured with `2>&1` and printed on failure.
  - A macOS package without an embedded `.pck` fails ("no .pck found"). The embedded-pack fallback for Windows and Linux also fails closed when it finds nothing.
- **Stdin in the build loop.** Godot runs as an async list, so its stdin is `/dev/null` in a non-interactive shell. The inventory script does not read stdin. Hosted confirms that all three presets ran.
- **Upload scope.** Both uploads use `if: always()`. `export-logs` is limited to `logs/` and `reports/`.
