## Ranked implementation findings

1. **P1 — A directory at the report pathname can make publication falsely succeed.** `tools/ci/lib/common.sh:1074–1087,1112–1126`, `tools/ci/ci.sh:1842–1846,1998–2002`. Plain two-operand `ln` interprets an existing destination directory as the directory in which to create a link named after the source basename. The macOS `ln(1)` manual confirms this behavior. If that child name is free, `ln` succeeds, `CI_REPORT` is set to the directory, and subsequent verdict appends fail at `common.sh:1098–1101`. The export can still return 0 because it does not gate success on that append (`ci.sh:2294–2299`). The same problem affects initial report reservation. Use an exact-destination, create-only link operation for both sites and cover a directory occupying the target name. An existence check alone would retain the publication race.

2. **P2 — Both namespace guards run after Godot has already been invoked.** `tools/ci/ci.sh:284–298,1860–1879,2013–2033`, `tools/ci/lib/common.sh:383–406`. `ci_find_godot` runs the selected binary with `--version` before either command is dispatched. Both guards independently check the lowercased main and derived sidecar names and run before destination lock acquisition, project import, and export. The derived sidecar currently always ends in `.pck`. The stronger before-engine requirement remains unmet. The wrapper at `tools/ci/tests/run_tests.sh:2582–2591` marks only `--export-*` and delegates `--version` to the real binary, so its green result cannot establish that the engine was never invoked.

## CI evidence and regression coverage

- **Regular-file and dangling-link collisions.** Both call sites retain their current report pointer when hard-link publication fails. A successful publication preserves the original name as an alias of the same inode. If the outer call fails and the worker later succeeds because the competing path disappears, the path printed by the outer process still points to the same report the worker updates. With a persistent regular file or dangling link, the current attempt continues to record its own verdict under its reserved name. The competing entry survives, and it can still look like this attempt’s canonical report to a consumer that reconstructs a filename. The emitted report path identifies the current attempt’s actual report. I found no stale-PASS borrowing through the report pointer on these two collision paths. `tools/ci/ci.sh:1842–1847,1904–1926,1996–2003,2345–2352`.
- **Attempt-bound inventory.** I checked the `6cb434c` attempt interface against the candidate. The run report records the attempt ID and full supplied SHA. The inventory name carries the preset, attempt ID, and SHA tag when supplied. The shipped checker creates that exact path with `O_EXCL`. A checker failure returns before the wrapper looks for a PASS and gets its own failure record. Success requires a regular, non-symlink inventory with the expected platform, main name, and PASS, followed by separate identity evidence. An occupied inventory path therefore fails through the shipped checker. The README’s claim that the wrapper guards the inventory name *before* running the checker is stale. `tools/ci/lib/common.sh:1042–1094`, `tools/ci/ci.sh:2203–2296`, `tools/export_smoke/lib/pack_inventory.py:520–525`, `tools/ci/README.md:122`.
- **Advisory lock lifetime.** The worker opens and acquires both destination locks before checking for existing outputs, including when invoked directly. The shell holds the descriptors through inventory, and the writer intentionally inherits them so a live writer remains protected after shell exit. Watchdogs close inherited descriptors before sleeping. This addresses the prior orphaned-watchdog mechanism. The structured timeout and full engine-log printer also address prior findings. The normal outer invocation supplies attempt-specific log and copy paths. A standalone `__export-inner` still falls back to shared log and project-copy paths, so its lock coverage applies to overlapping destinations and does not establish scratch isolation for disjoint standalone calls. `tools/ci/ci.sh:1904–1909,1943–1978,2035–2108`, `tools/ci/lib/common.sh:79–115,130–164,690–706`.
