# Fallback engine pin for tools/ci (PLAN.md M0.1).
#
# tools/ci/lib/common.sh reads this file only when the project does not carry
# tools/toolchain/pin/engine.txt, which is the M0.1 record and therefore the
# authoritative pin (version, official sources, observed digests and upstream
# verification status). Keeping the fallback here means a standalone checkout of
# tools/ci/ still pins the engine instead of accepting whatever is installed.
#
# Version authority: the official Godot download archive
#   https://godotengine.org/download/archive/
# Do not track a moving "stable" download (docs/TECHNICAL_DESIGN.md).
#
# Fields read by the tooling:
#   major/minor/patch  exact engine version required by every CI check
#   tag                official release tag
#   version_string     exact `--version` output of the pinned build (advisory:
#                      another host's official build of the same version may
#                      print a different build string, so a mismatch is a
#                      warning, not a failure)
#   upstream_verified  no | yes - whether the digests recorded HERE have been
#                      compared against the publisher's checksum file. `no` must
#                      never be reported as verified.
#   release_archive_url
#                      official release asset downloaded by CI on runners that
#                      do not provide GODOT_BIN
#   release_checksums_url
#                      the publisher's checksum file for the pinned tag
#   release_archive_sha512
#                      publisher's SHA-512 digest of release_archive_url (the
#                      pinned release artifact). This is what
#                      `ci.sh verify-engine` checks BEFORE extraction.
#   release_archive_sha256
#                      locally computed SHA-256 of the same verified download
#   release_binary_sha256
#                      locally computed SHA-256 of the editor binary inside
#                      release_archive_url, checked BEFORE it is executed
#   templates_url
#                      official export-template archive (.tpz) that CI downloads
#                      and verifies before extraction (Opus recheck finding E1)
#   templates_archive_sha512
#                      publisher's SHA-512 digest of templates_url. This is what
#                      `ci.sh verify-templates` checks BEFORE extraction.
#
# Why digests live here after all: a digest recorded on one host for an
# *installed* file is not a portable expectation for another host, so those stay
# in tools/toolchain/pin/checksums.txt. A digest of a *published release
# artifact* is different: the publisher publishes it, every host downloads the
# same bytes, and CI is exactly the place that must refuse to extract or run an
# archive it did not expect. That is the M0.1 requirement ("with checksums.
# Verify before installation"), so the artifact digests are recorded here and
# verified by `ci.sh verify-engine` and by .github/workflows/ci.yml.
#
# Never invent, guess or copy a digest from an unofficial mirror. An empty field
# means "not recorded" and is reported as such, never treated as verified.

# Scope: the export-template archive itself. CI verifies THIS digest before
# extracting anything from it (PLAN.md M0.1: "Verify before installation"), then
# installs the <version>.stable tree where the engine reads it and verifies the
# installed tree's version.txt and required templates. Per-file digests of the
# extracted templates are NOT recorded here: a digest of a file inside a
# publisher-verified archive adds no portable expectation, and the installed
# copies belong to tools/toolchain/pin/checksums.txt (local observations).
#
# Why the templates are pinned at all: the hosted export-preparation job used to
# install no templates, so `export --check` failed on a fresh runner for all
# three targets, and pointing GODOT_TEMPLATES_DIR at a template tree would have
# made the check pass while the engine still refused to export (the engine does
# not read that variable). Verifying the archive before extraction and
# installing it into the engine's own directory is the fix for both halves.
